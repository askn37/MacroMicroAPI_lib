# Logic_Analyzer.ino

このサンプルスケッチは以下について記述している；

- GPIOキャプチャによる簡易ロジックアナライザー

## 対象AVR

- modernAVR世代
  - AVR-Dx/Ex/Lx/Sx系統
  - Dx系統の SRAM 8KiB モデル推奨

## GPIOの通信状態を可視化する

I2C や SPI の絡む低レベルな通信階層の虫取りなどをやっていると、GPIOの変化を時系列で追いたいということはよくある。そういう時にはロジックアナライザーを持ち出すわけだが、ちゃんとしたのはそれなりに高価だし、USBドングル型の廉価品も専用アプリや各OS向けドライバーを準備するのは面倒だし、だったらその辺にある適当なマイコンで GPIOキャプチャして、シリアルコンソール表示できるだけでも用が足りるのではないか？と考えてサクッと書いてみたスケッチがこれだ。250kbps程度まで追えて、8KiBの SRAMで 1400ポイント弱のキャプチャができ、1/32 usec精度の表示ができるだけ、という原始的なものだが、それでも一応モノの役に立つ。

仕組みは単純。特定のポートグループを読み、キャプチャテーブルに格納するだけ。トリガーとキャプチャには BOTHEDGES 割込を用い、それにタイムアウト停止用のタイマーを加えている。

```
/*
 * Set of ports to visualize.
 */
#define CPATURE_GPIN PIN_PC0
#define CAPTURE_MASK (PIN1_bm|PIN0_bm)
#define CAPTURE_TRIGER (PIN1_bm|PIN0_bm)
```

設定可能項目は三つ。`CPATURE_GPIN`には監視対象となるポートグループの代表ピンを書く。このピンが属する最大8ピンが監視対象だ。

`CAPTURE_MASK`にはキャプチャしたいピンをビットマスクで指定する。前述のピン自体は含まなくても良い。指定しないビットに相当するピンは常に0として読まれる。

`CAPTURE_TRIGER`にはトリガーにしたいピンをビットマスクで指定する。これも前述の`CAPTURE_MASK`に含まれていなくても良い。指定ピンのエッジ変化がトリガーとなるので、一般にはクロック信号を指定する。つまり SPI でいえば `SCK`（クロック信号）と`SS`（開始と終了）をトリガーに指定する。`MISO`と `MOSI`（共にレベル変化信号）はそれに追従してサンプリングされるべきなので、`CAPTURE_MASK`にだけ含めるようにする。

しかし全てのピンは`CPATURE_GPIN`が示すポート群に属していなければならない。

> [!CAUTION]
> `CAPTURE_MASK`指定ピンは`Hi-Z`に設定されるため、必ずどこかに配線されていなければならない。同一ポート群のその他のピンは未使用とマークされるので、N.C.=浮いていても良い。<br/>
> <br/>
> このスケッチをインストールする観測側ボードと、観測対象の動作電圧は 同一でなければならず、故に VCC/GND も繋げなくてはならない。観測側が AVR-DA/DB/DD であるなら、VDD2ピンによる MVIO機能を用いて（5.5V未満の）異電圧接続が可能だが、その場合は必ず PORTC ポート群をキャプチャー用に指定しなければならない。（かつ `SYSCFG1` フューズの、`MVSYSCFG[1,0]` ビットを `DUAL` 値に指定する）

ビルドする時の`F_CPU`は可能な限り高速な方が良い。故に`32 MHz`が指定可能な AVR-Dx系統は有利だ。トリガー起動される割込ベクターは 120 CPUサイクル程度を消費し、かつその間のキャプチャは（トリガーは補足できても）記録が遅延または欠損するため、理論サンプリング周波数は 250kbps強となる。最速`20 MHz`の品種では 170 kbps弱までしか取れない。

左からキャプチャ番号、最初のトリガーからの累積時間（usec）、前のトリガーからの経過時間（usec）、キャプチャされたポート群のビット列 2進数表示だ。
最初の 0番は、キャプチャに入る前の ポート情報を示しているので、これと 1番についての時間情報はない。
経過時間は、その右上のポート群が継続していた時間として読める。なので最終行の ポート群表示は、タイムアウトに達した際の最終状態である。

経過時間は **[コード実行時間を計測するベンチマーク実演（TCB2組32bit計数器使用）]** と同じ、`F_CPU`速度刻みの 32bit連結タイマーに依っている。
この 32bit値をキャプチャテーブルに書くための、レジスタPUSH／POPに消費する CPUクロック量が死重になって、サンプリング時間精度を下げている。

タイムアウト終了には RTC_PIT 定期割込を用いた。これもタイミングによってはサンプリング時間精度を乱し、ジッターとして観測される場合がある。
このタイムアウトの規定値は約2秒だが、これは`TIMEOUT_SEC`定義で加減できる。
